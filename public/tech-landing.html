Technical overview

Under the hood

UnScribble is a transcription aid—not a clinical decision system. This page documents the multi-agent decode pipeline, deterministic safety layer, image preprocessing, and vanilla frontend that turns handwritten prescriptions into structured, reviewable output.

two-tier
Section 01

System architecture

A thin HTTP server serves static assets and orchestrates a staged agent workflow. All decode intelligence lives server-side under agents/; the browser handles capture, optional preprocessing, SSE progress, and rich result visualization.

Client

Vanilla frontend (public/)

ES modules, Canvas/Web Worker image enhancement, fetch + ReadableStream on /api/decode/stream, results & medication detail views (3D protein, body map).

↓
Transport

HTTP + Server-Sent Events

POST /api/decode/stream emits workflow.start, per-agent progress, and workflow.complete. Batch JSON at POST /api/decode.

↓
Server

server.js

Static file host, route handlers, env loading. Binds 127.0.0.1:${PORT||3000}. No build step.

↓
Orchestrator

agents/orchestrator.js

Staged workflow, parallel Stage 2, self-consistency re-run, merger, formulary validation, SHA-256 LRU cache (16 entries, 5 min TTL).

↓
Model API

NVIDIA Inference (NIM)

Vision + text agents via Responses API (nim-client.js). Structured JSON with strict schemas; mock mode via WORKFLOW_MOCK=1.

Decode pipeline

Stages run sequentially except Stage 2 (three agents in parallel). Unusable images short-circuit after quality check; formulary validation always runs at the end.

the team
Section 04

Seven agents

Each agent has a strict JSON schema (additionalProperties: false), dedicated prompts, and a thin runner in agents/agents/. Critical agents fail the whole workflow on error; others degrade gracefully.

Image quality

image_quality
Vision

Assesses legibility, blur, lighting, and recommends preprocessing (original, contrast, mono). If unusable, downstream extraction is skipped.

Out: image_quality.legibility, recommended_preprocessing

Raw transcription

raw_transcription
Vision Critical

Line-by-line OCR-style transcription with uncertainty markers. Infers region_hint (UK/US/India style) to steer abbreviation expansion in later agents.

Out: raw_transcription[], region_hint

Patient header

patient_header
Text

Extracts patient demographics, prescriber, clinic, dates from transcribed text. Runs in parallel with medications and clinical context.

Out: patient object

Medications

medications
Text Critical

Structured drug rows: name, strength, form, dose, frequency, duration, PRN flags, confidence scores, LASA-aware alternatives. May re-run with temperature nudge for low-confidence lines.

Out: medications[] with medication_name_confidence

Clinical context

clinical_context
Text

Diagnoses, allergies, advice, follow-up instructions. Uses regionDirective() for locale-specific schedule abbreviations (BD, TDS, QID, etc.).

Out: clinical_context, allergies, abbreviations

Safety review

safety_review
Deterministic

Rule engine in safety-rules.js—flags low legibility, missing dose/frequency, uncertain tokens, high-risk abbreviations (STAT, IU, MSO4, µg).

Out: requires_human_review, review_reason

Summary

synthesis
Text

Patient-friendly narrative summary from merged artifacts. Skippable via WORKFLOW_SKIP_SYNTHESIS=1 for a deterministic template from merger.js.

Out: summary

math & rules
Section 05

Key algorithms

A mix of classical image processing, edit-distance search, and deterministic merge logic—no black-box scoring on safety.

1

CLAHE (Contrast Limited Adaptive Histogram Equalization)

Client-side enhancement in image-enhance.js. Tiles the grayscale image, clips histogram peaks, and redistributes contrast locally—helps faded or uneven lighting before the vision model sees the image.

Mode: enhancementMode = "contrast" → applyCLAHE(imageData)
2

Sauvola adaptive thresholding

Local mean + standard deviation per window (radius 12, k=0.2, R=128) binarizes ink vs paper—ideal for mono mode on noisy phone photos.

T(x,y) = mean · (1 + k · (σ/R − 1)) → ink if gray < T
3

Formulary fuzzy match (Levenshtein)

After LLM extraction, drug names are validated against a JSON formulary. Candidates are bucketed by length; fastest-levenshtein finds distance ≤ 2. Distance-1 with a single unambiguous match auto-corrects the name (original kept in medication_name_raw).

dedup key: (name|strength|form) → promote | alternatives | cap confidence
4

Self-consistency merge

When medication name confidence < 0.7 or uncertainty markers exist (≤6 rows), a second medications pass runs with temperatureNudge and LASA-focused context. mergeMedicationRuns picks per line: agree → max confidence; disagree + higher conf + in formulary → second pass; else flag disagreement.

5

Workflow LRU cache

SHA-256 of imageDataUrl|originalImageDataUrl keys a 16-entry LRU with 5-minute TTL. Cache hits emit only workflow.start + workflow.complete with cached: true.

cacheKey = sha256(image + "|" + originalImage)
6

LASA (look-alike sound-alike) guardrails

medical-context.js maintains LASA pairs and injects focused blocks on re-runs when first-pass drug names are ambiguous—reducing swaps like hydroxyzine / hydralazine.

Section 06

API & streaming

Routes

  • GET /api/config — model, agents[], mock flag
  • POST /api/decode/stream — primary SSE decode
  • POST /api/decode — batch JSON + events[]
workflow.start

{ workflowId, agents: [{ id, label }] }

agent.start / agent.complete

Per-agent progress; summaries only (no full PHI in stream)

workflow.complete

{ result, workflow: { steps, totalMs, model, cached? } }

workflow.error

{ message, agentId? } on critical failure

  "image_quality",

  "review_reason"
}

Frontend decode client
